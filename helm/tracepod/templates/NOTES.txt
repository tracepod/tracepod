IMPORTANT: The sensor requires containerd with NRI enabled — it is its only
container-discovery mechanism. Before trusting a green rollout, run on a node:

  ./hack/discovery-probe.sh

or, with no node/SSH access, via a node-debug pod (host filesystem is at
/host there, not /):

  kubectl debug node/<name> -it --image=ubuntu:24.04 -- bash
  # then, inside the debug pod:
  apt-get update -qq && apt-get install -y -qq curl socat
  curl -fsSLO https://raw.githubusercontent.com/tracepod/tracepod/main/hack/discovery-probe.sh
  HOST_ROOT=/host bash discovery-probe.sh

Exit 1 means NRI is unreachable — this install will trace nothing.

If NRI is unavailable, the sensor pod now exits and CrashLoopBackOffs (logs
say "NRI unavailable") instead of running quietly while tracing nothing — it
recovers on its own once NRI is enabled on the node (kubelet backoff, up to
~5 min between restarts).

Containers started with docker run or nerdctl run are NOT profiled.
Only containers started through the Kubernetes CRI (kubelet) are observed.

STANDALONE MODE — profiles are written to each node at:
  {{ .Values.sensor.profileHostPath }}/<container-id>/files.json

After a container stops, retrieve its profile with:

  # Find the sensor pod on the node where your container ran:
  NODE=$(kubectl get pod <your-pod> -o jsonpath='{.spec.nodeName}')
  SENSOR=$(kubectl -n {{ .Release.Namespace }} get pod \
    -l app.kubernetes.io/name=tracepod-sensor \
    --field-selector spec.nodeName=$NODE \
    -o jsonpath='{.items[0].metadata.name}')

  # List available profiles:
  kubectl -n {{ .Release.Namespace }} exec $SENSOR -- ls /profiles/

  # Copy a profile to your local machine:
  kubectl -n {{ .Release.Namespace }} exec $SENSOR -- \
    cat /profiles/<container-id>/files.json > files.json

Then build a hardened image from the profile:

  harden build \
    --manifest files.json \
    --source   <your-image-ref> \
    --output   /tmp/hardened
