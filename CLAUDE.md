## Project Overview

**Tracepod** is an open-source eBPF-based container profiling toolkit. It observes which files
a running container actually accesses at runtime — via eBPF kernel tracing — and produces:

- Minimised OCI images (only files actually observed at runtime)
- Seccomp syscall allowlist profiles
- CycloneDX + SPDX SBOMs

License: AGPL-3.0. Brand name: **Tracepod**. OCI labels use `com.tracepod.*` prefix.

## Tech Stack

- **Language:** Go 1.26, `CGO_ENABLED=0` always
- **eBPF:** `cilium/ebpf` (CO-RE, pure Go, bpf2go codegen)
- **OCI:** `google/go-containerregistry` (image pull/push)
- **Container runtime:** containerd NRI hooks (`containerd/nri`)
- **Kubernetes:** `k8s.io/client-go` (workload metadata in DaemonSet mode)
- **Kernel targets:** 6.8 (ubuntu-22.04 Azure runner), 6.17 (ubuntu-latest Azure runner)
- **Dev environment:** Ubuntu 24.04 Lima VM (QEMU — required for kprobe attachment)

## Architecture

Full detail in `docs/architecture.md`. Summary:

1. **eBPF sensor** attaches THREE kprobes:
   - `kprobe/do_sys_openat2` — file opens; raw user-space path captured; relative paths
     resolved in userspace via `/proc/<pid>/cwd` + `cgroup.procs` fallback (see below)
   - `kprobe/security_bprm_check` — execve; captures binary path + shebang interpreter
   - `kprobe/security_mmap_file` — PROT_EXEC mmap; basename-only; correlated against
     paths already recorded by the openat probe

2. **Cgroup filtering** — only events from containers in the `allowed_cgroups` BPF map are
   emitted; the NRI plugin (`internal/container/nri.go`) manages that map at container
   start/stop

3. **Per-container aggregators** (`manifest/aggregator.go`) accumulate events during the
   container's lifetime; snapshot written on stop

4. **Manifest output** — written to `profiles/<container-id>/files.json` (standalone) or
   POSTed to a controller (`--controller-url`, DaemonSet mode)

5. **Hardener** — reads manifest → resolves ELF deps → builds scratch OCI layer → push

## CWD Resolution (critical for relative-path openat events)

`bpf_get_current_pid_tgid()` returns the PID in the outermost kernel PID namespace.
In nested environments (e.g. kind-in-Lima VM) the sensor's `/proc` only exposes
kind-node-level PIDs, so a direct `/proc/<bpf_pid>/cwd` readlink fails silently.

The fallback (`cwdForEvent` in `cmd/sensor/main.go`):
1. Try `os.Readlink("/proc/<bpf_pid>/cwd")` — fast path, works in production (hostPID:true)
2. If that fails, read `<cgroupFSPath>/cgroup.procs` to get a locally-visible PID,
   then readlink its cwd

`cgroupFSPath` is passed from the NRI `onStart` callback down to the router and stored
per cgroup. This path comes from `ctr.GetLinux().GetCgroupsPath()` resolved to the
absolute `/sys/fs/cgroup/...` path.

## Testing Patterns

- Standard `go test`, no external framework
- Linux-specific tests (`internal/container/`, `internal/ringbuf/`) skip on macOS
- CI skips `internal/probe` and `cmd/sensor` (need BPF toolchain); full suite runs in Lima VM
- BPF object codegen (`make generate`) required before building or testing `internal/probe`
- arm64 BPF objects are committed to git; amd64 objects are generated during release CI

## Commit Conventions

[Conventional Commits](https://www.conventionalcommits.org/) required:

```
feat(manifest): add observation source to aggregator
fix(sensor): capture CWD-relative paths via cgroup.procs fallback
docs: update architecture overview
test(hardener): add elf resolver edge-case tests
```

## Critical Constraints

**`CGO_ENABLED=0` must be preserved.** Every binary must build with `CGO_ENABLED=0 go build ./...`.
Do not introduce any cgo dependency.

**Do NOT use `bpf_d_path()`.** It is blocked by the BPF verifier in kprobe context, and
overlayfs dentry is not visible in the container's mount namespace — it returns errors
consistently in containerised overlay2 environments. CWD resolution uses `/proc` + `cgroup.procs`.

**Correctness over features.** A minimised image that crashes in production is unacceptable.
The ELF dependency resolver must handle `rpath`, `RUNPATH`, `LD_LIBRARY_PATH`, `/etc/ld.so.conf.d/`
includes, and `dlopen()` patterns. Test against real workloads before shipping.

**Do not flatten observation source.** The `source` field in the manifest schema
(`direct` / `inferred-elf` / `directory-inclusion` / `manual`) is load-bearing for
confidence scoring and audit trails. Do not simplify it away.

## Key Architectural Decisions

| Decision | Choice | Rationale |
|----------|--------|-----------|
| eBPF library | cilium/ebpf | Pure Go, CO-RE, matches Tetragon/Cilium ecosystem |
| Container integration | NRI hooks | Well-defined lifecycle; avoids polling race window |
| CWD resolution | /proc + cgroup.procs fallback | Handles nested PID namespaces (kind-in-Lima) |
| Probe selection | kprobe/do_sys_openat2 | fentry/vfs_open rejected by verifier or overlayfs in practice |
| Observation source field | Required | Foundation for confidence scoring and audit trails |
| CGO disabled | Always | Clean cross-compilation; no libc dependency |
| SBOM formats | CycloneDX + SPDX | Enterprise tooling requires whichever one their tool doesn't support |
